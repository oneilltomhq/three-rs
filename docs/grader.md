# The grader

Every graded example is judged by three.js' own end-to-end image test,
`test/e2e/` in the three.js checkout (`puppeteer.js`, `image.js`,
`deterministic-injection.js`), against three's reference screenshots in
`examples/screenshots/<example>.jpg`. `tests/e2e/main.rs` renders the port's
frame and hands it to three's comparator. These are the facts it must
reproduce exactly, because three's screenshots were taken under them:

- **Viewport 800x500.** The screenshot is downscaled by half to 400x250 with
  `image.js`'s `scale()`, a box filter. The harness runs that function under
  node rather than porting it.
- **One frame.** `performance.now()` and `Date.now()` return 0 and
  `requestAnimationFrame` fires once, so an example is graded at time zero.
- **`Math.random`** is `x = Math.sin( seed ++ ) * 10000; return x - Math.floor( x )`,
  with `seed` starting at `Math.PI / 4`. `three_rs::testing::DeterministicRandom`
  replicates it bit for bit in f64, and every example that calls
  `Math.random` uses it.
- **`window.TESTING = true`.** A few examples branch on it; their ports take
  the testing branch.
- **Pass** is pixelmatch at threshold 0.1 *and* fewer than 0.1% of pixels
  different: at most 100 of the 100000 in the downscaled frame. The
  comparison is `image.js`'s `compare()`, unchanged
  (`three_rs::testing::compare` runs it under node).

## Calibration

Three's stock e2e runner rendered black on the development machine, so
before any port was graded, three's *own* frames were run through the
unmodified grader on the same Intel Iris Xe the port is graded on
(`rung0/RUNG0.md`). `rung0/grader-flags.patch` is what made that possible: the stock
runner forces lavapipe and passes `--disable-vulkan-surface`, and the patch
drops both for `--use-angle=vulkan`. It is only needed to run three's own
suite, not the port's. Examples where three itself
fails its own screenshot on this hardware, such as `webgpu_camera` (0.9% of
pixels on point and line coverage), are not graded: no port could pass them
honestly.

## What keeps a pass honest

The rules are in `CONTRIBUTING.md` under *Things the grader assumes*: the
comparator and its threshold are three's, unmodified; nothing derived from
a reference screenshot is in the tree; every example goes through the same
route (scene graph, node materials, WGSL generated by the `NodeBuilder`
port, wgpu), with no hand-written shaders.

Failures on this stack are silent wrong pixels, not errors. A draw count or
the absence of a panic proves nothing; the diff does. So a rung is done when
the grader passes *and* someone has looked at `actual.png`, the reference
and the diff strip under `target/e2e/<example>/`.
